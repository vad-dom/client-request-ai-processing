# Neowise — AI-помощник для входящих заявок

[Исходная постановка задачи](ORIGINAL-README.md)

Веб-приложение для первичного разбора входящих клиентских заявок. Менеджер вводит текст заявки, получает её тему и черновик ответа. При сбое AI или недоступности API приложение предлагает ручную обработку.

Менеджер самостоятельно проверяет результат и принимает решение об отправке ответа клиенту. Автоматическая отправка не предусмотрена.

## Требования

- Node.js 20 или новее.
- Внешние зависимости и API-ключи не требуются.

## Запуск

```sh
node server.mjs
```

Открыть в браузере: http://127.0.0.1:3000.

Порт можно изменить через переменную окружения `PORT`.

## Автоматические тесты

```sh
node --test triage.test.mjs
```

Предварительно запускать сервер не требуется.

Используется встроенный тестовый инструмент `node:test`.

Два автоматических теста проверяют:

- API: обработку неизвестной темы и пустого черновика AI, HTTP-статус и структуру ответа `manual_review`.
- Frontend: очистку предыдущего черновика и игнорирование устаревшего ответа при обратном порядке завершения запросов.

Frontend-тест выполняет JavaScript приложения с имитацией DOM и HTTP-ответов, без запуска браузера.

## API

`POST /api/triage`

Тело запроса:

```json
{
  "text": "Когда будет доставка?"
}
```

### Успешная обработка — HTTP 200

```json
{
  "status": "ready",
  "topic": "delivery",
  "draft": "Спасибо за обращение. Уточним детали заявки."
}
```

Допустимые темы: `delivery`, `pricing`, `other`.

### Некорректный ввод — HTTP 400

```json
{
  "status": "invalid_input"
}
```

Возвращается при некорректном JSON, отсутствующем поле `text`, нестроковом значении или строке, пустой после удаления пробельных символов по краям.

### Требуется ручная обработка — HTTP 200

```json
{
  "status": "manual_review",
  "topic": null,
  "draft": null
}
```

Возвращается при таймауте, исключении AI или некорректном результате модели.

## Обработка ошибок

- Входные данные проверяются на сервере до вызова AI.
- Ожидание AI ограничено 300 мс с помощью `AbortSignal.timeout()`.
- Результат AI проверяется на корректность JSON, допустимость темы и наличие непустого строкового черновика.
- При отправке новой заявки предыдущий результат очищается.
- При сбое AI, сетевой ошибке или неожиданном HTTP-статусе либо бизнес-статусе API интерфейс предлагает ручную обработку, сохраняя введённый текст заявки.
- Счётчик запросов на frontend предотвращает перезапись актуального результата устаревшими ответами и ошибками.

## Ручная проверка

Имитатор AI поддерживает специальные маркеры для воспроизведения сбоев:

| Входной текст | Ожидаемый результат |
|---|---|
| Когда будет доставка? | Готово, тема «Доставка» |
| Какая стоимость? | Готово, тема «Цены» |
| Здравствуйте! | Готово, тема «Другое» |
| Пустая строка или пробелы | Сообщение о некорректном вводе |
| `[timeout]` | Ручная обработка примерно через 300 мс |
| `[error]` | Ручная обработка |
| `[bad-json]` | Ручная обработка |
| `[bad-topic]` | Ручная обработка |
| `[empty-draft]` | Ручная обработка |

Для проверки сетевой ошибки можно остановить сервер и отправить новую заявку, не обновляя страницу браузера.

Во всех сценариях сбоя предыдущий черновик должен отсутствовать.

## Что дает менеджеру

Приложение помогает сократить время первичного разбора заявок и подготовки ответов, сохраняя контроль за менеджером; эффективность можно оценить, например, сравнением среднего времени обработки одной заявки и доли правильно классифицированных заявок при ручной и AI-assisted обработке.
